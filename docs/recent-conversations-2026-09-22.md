## 1. 需求演进与最终决定

1. 最初希望展示 A、B 两队信息相撞，B 队被击退、打叉和碎裂，A 队获胜。
2. 保留原工程及 HDMI 输出，开机自动轮播；K2 不再作为本地上一张按键，改为触发动画。串口屏上一张命令保留。
3. 用户认为动画叠在轮播上不够完整，要求轮播和动画成为互斥显示模式。
4. 改成独立全屏动画；期间停自动换图和背景音乐。已开始的 SD 事务正常结束，SDRAM 刷新及 HDMI 时序不能停止。
5. 查阅 RoboMaster、Apex 胜利结算和电竞包装参考后，放弃击碎败方表现。
6. 最终只展示蓝方获胜，不出现红方、VS、红叉或碎片。
7. 先制作浏览器预览，再移植为 FPGA 实时渲染，采用专用抗锯齿文字 ROM。
8. 进一步把标题改成三段斜切片错位滑入、最后拼合；背景改成三块有间隙的斜板，取消全宽长方形色带。

参考是风格方向，并非复制 Apex 原作素材或承诺完全相同的表现。

## 2. 当前 K2 交互

| 状态 | 行为 | K2 |
|---|---|---|
| IDLE / 轮播 | 开机自动轮播、正常背景音乐 | 下一帧开始动画 |
| PLAY / 动画 | 蓝色切入、队徽、标题分片拼合及扫光 | 忽略，防止误触 |
| HOLD / 保持 | 动画完成后永久保持胜利画面 | 下一帧返回轮播 |

- 动画约 360 帧，当前刷新率下约 6 秒。
- PLAY 中的按键不会排队成为结束后的返回命令。
- 返回轮播后可以再次按 K2 播放。
- 复位回到轮播。
- 设置页和正式比赛中的 K2 原有含义仍由上层模式控制。
- 暂停轮播不等于动态释放其 LUT/BRAM；这是显示内容与业务活动的切换。

## 3. HDMI 链路

```text
TF 卡图片 / 帧缓存
 → 亮度、对比度、饱和度、锐度及串口屏滤镜
 → OSD / 信息叠层
 → 蓝方胜利模块（轮播透传，动画与保持时替换整帧）
 → RGB 转视频流
 → HDMI 发送核
 → HDMI PHY 差分串行输出
 → 开发板 HDMI_A → 显示器
```

- 画面不是经串口传入，也不是播放 HTML；由 FPGA 逐像素绘制。
- 当前有效分辨率为 1280×720。
- 像素时钟约 75 MHz，行总长 1650、帧总高 750；计算刷新率约 60.6 Hz，不是严格标准 60 Hz。
- 动画输出 RGB、DE、VS 同步流水；进度在帧边界更新。
- HOLD 只冻结动画状态，不停止 HDMI 扫描，否则显示器会断流。
- 当前使用 HDMI_A，不是 HDMI_B。
- 发送核同时连接音频数据，动画/保持期间背景音乐暂停。

## 5. 陶晶驰 HMI 工程与命令

源文件为 saixian-main/saixian_UART_HMI.HMI。
提取时区分有效文件表记录与废弃记录；有效 Program.s 使用 115200，文件里搜到的 9600 属于旧记录。
有效页面：home、settings、game。

串口配置：115200，8 数据位，无校验，1 停止位。
固定帧：55 CMD VALUE 00 FF FF FF，参数是二进制单字节。

| CMD（十六进制） | 操作 | VALUE |
|---|---|---|
| 01 | 开始比赛 | 00 |
| 02 | 暂停 / 继续切换 | 00 |
| 03 | 结束比赛 | 00 |
| 04 | 上一张（轮播模式） | 00 |
| 05 | 下一张（轮播模式） | 00 |
| 10 | 锐度 | 0–3 |
| 11 | 亮度 | 0–100 |
| 12 | 对比度 | 0–100 |
| 13 | 饱和度 | 0–100 |
| 14 | 音量 | 0–100 |
| 15 | 反色 | 0 / 1 |
| 16 | 复古 | 0 / 1 |
| 1F | 恢复默认 | 00 |

例：亮度 50 为 55 11 32 00 FF FF FF；32 是十六进制，不是 ASCII “50”。

本地适配已完成：
- 保留原动作命令及五项参数映射。
- 增加 15、16 解析、开关状态与图像滤镜；默认恢复同时关闭两项滤镜。
- 复古是亮度加暖色的低成本近似；两项均开启时先复古、后反色。
- 滤镜只影响背景图片，不改变 OSD 和蓝方动画。
- 增加约 40 比特周期的残缺帧接收超时恢复；非法开关参数拒绝。
- 仿真覆盖全部 13 个编号、启动噪声、未知命令、坏帧恢复及颜色结果。

## 6. 物理连接与电平纠正

经项目 GPIO 原理图与约束核对：
- 屏幕 TX → FPGA RX：J1 第 1 脚 GPIOA_0，对应 D14。
- 屏幕 GND、电源负极与开发板 GND 共地；J1 第 12 脚为 GND。
- FPGA TX 为 J1 第 2 脚 GPIOA_1，对应 G11；当前没有回传，屏幕 RX 可暂不连接。
- 屏幕按实际型号的供电要求供电，不从 FPGA GPIO 取电。
- 接线必须依据板上 J1 的 1 脚标记，不能把 FPGA 球位 D14 当排针编号。

纠正早期过度概括：5V 供电不等于 TX 一定为 5V。
必须确认实物型号及 TTL/RS232 配置：
- 3.3V TTL：确认规格兼容后可连接 FPGA RX。
- 5V TTL：先做 5V→3.3V 电平转换。
- RS232：不能直接接 FPGA GPIO，需对应收发器。

下载串口屏时，避免 USB 转串口与 FPGA 两个发送端并联。完整电气兼容性尚未在实物验证。

## 7. 串口屏计时过快：诊断结论与修改建议

用户希望仅获得编辑器修改方法，未授权本轮直接改 HMI 二进制文件。

- 之前提取到的计时器名为 tm0；t0 是另一控件名，计时显示代码实际写入 t4.txt。
- 用户提供的事件每执行一次 n_total.val 加 1，因此应把 tm0.tim 设为 1000 ms。
- 检查其他事件是否再次写小 tm0.tim；不要在计时器事件内重复开关自身来补偿。
- 使用手机秒表检查现实 10 秒是否约增加 10 秒，区分“走速过快”和“固定领先”。
- **实际当前 tim 值未核实**：尝试读取时 HMI 正被编辑器占用。不能认定用户原值一定是 100 或其他数值。
- FPGA 有准备、3/2/1 和开始提示等阶段，正常首次启动约 6 秒后进入正式计时；屏幕原本入页立即计时。
- FPGA 与屏幕独立计时，调 tim 无法保证同起点、暂停恢复和长期同步。
- 原屏幕代码在 60 秒封顶，FPGA 计时则可继续，属于另一处语义差异。

## 8. 三秒倒计时提案（仅提供代码，未核实已应用）

目标：
- 入页 00:03 / j0=100。
- 第 1 秒 00:02 / 66。
- 第 2 秒 00:01 / 33。
- 第 3 秒 00:00 / 0，转入比赛阶段。
- 此后正计时至 01:00，j0 从 0 增至 100。

新增数值变量 va_phase（0 倒计时、1 比赛）及 va_count。

页面后初始化：
```text
tm0.en=0
tm0.tim=1000
va_phase.val=0
va_count.val=3
n_total.val=0
n_min.val=0
n_sec.val=0
t4.txt="00:03"
j0.val=100
tm0.en=1
```

定时事件的外层分支：
```text
if(va_phase.val==0)
{
  if(va_count.val>0)
  {
    va_count.val=va_count.val-1
  }
  cov va_count.val,t_tmp.txt,0
  t4.txt="00:0"+t_tmp.txt
  j0.val=va_count.val*100/3
  if(va_count.val==0)
  {
    va_phase.val=1
    n_total.val=0
    n_min.val=0
    n_sec.val=0
  }
}else
{
  // 此处保留原比赛正计时及 mm:ss 格式化代码
  // 到 60 秒时显示 01:00、j0=100、tm0.en=0
}
```

以上是阶段结构摘录，不是完整可替换的比赛分支。
进度条每秒跳变，不是平滑动画。
该提案只改变屏幕本地显示，并未同步 FPGA。
不要在倒计时末尾额外发送开始命令来碰运气同步，可能改变 FPGA 原有状态流程。

## 9. FPGA 默认值与屏幕建议显示

上电与 1F 恢复默认一致：

| 参数 | FPGA 内部默认 | 屏幕建议 val |
|---|---:|---:|
| 锐度 | 1 / 0–3 | 1 |
| 亮度 | 4 / 0–8 | 50 |
| 对比度 | 4 / 0–8 | 50 |
| 饱和度 | 4 / 0–8 | 50 |
| 音量 | 5 / 0–8 | 63 |
| 反色 | 关闭 | 0 |
| 复古 | 关闭 | 0 |

63 只是映射到音量第 5 档的滑块值，不是精确的 63% 音频增益。
0–100 的设置按阈值量化到 9 档，亮度 50 表示中性档，并非屏幕背光的一半。

恢复默认按钮建议：
```text
h_sharp.val=1
h_bright.val=50
h_contrast.val=50
h_saturation.val=50
h_volume.val=63
n_sharp.val=1
n_bright.val=50
n_contrast.val=50
n_saturation.val=50
n_volume.val=63
bt_invert.val=0
bt_vintage.val=0
printh 55 1f 00 00 ff ff ff
```

不要每次进入设置页都强行赋默认值而不同步硬件，否则显示值与实际参数不一致。跨页控件值保持及状态回读仍需另行处理。
