# 音频修复 V4：减少滋滋声，保留清晰度和音乐响度

本轮基于当前 V3 源码继续优化。V3 的 31 抽头低通在 5 kHz 已衰减约 1.34 dB，在 7.5 kHz 仅衰减约 17.82 dB；音乐细节和噪声均落在较宽的过渡带。直流清理在 20 Hz 还会衰减约 1.92 dB。V2 的两级递归低通则会更早削弱音乐高频。

## 最终实现

- 使用 63 抽头、Q12 对称 FIR，系数总和严格为 4096。40 Hz–5 kHz 的主要音乐频段接近原增益，过渡带更陡；6 kHz 约 −2.37 dB，7.5 kHz 约 −35.99 dB，8 kHz 约 −60.20 dB。
- 直流跟踪从每样本 1/512 改为 1/2048，低频截止从约 15 Hz 降至约 3.7 Hz。20 Hz 衰减缩小到约 0.15 dB，40 Hz 约 0.04 dB。
- 孤立爆音检测最低门限从 4096 降为 1024 LSB，但门限随前后邻居能量提高，邻居一致性检查也更严格。可以修复静音附近较小的孤立尖峰，降低高频音乐误判风险；连续多样本干扰仍不能直接插值修复。
- 保留峰值保护和 256 样本开关渐变，不对整段音乐应用噪声门，也不整体提高增益。
- 两声道继续复用一个 FIR 乘加器和 4 块 RAM9K，历史深度从 32 增至 64。干湿路径对齐至 32 个样本，延迟约 0.667 ms；最小支持样本间隔 300 个时钟，实际播放超过 1500 个时钟。按键、串口屏和提示音路径沿用原实现。

尝试过按强度恢复高频的候选，但同一噪声测试曲会带回部分噪声，因此最终版本使用更陡的固定 FIR。验证目录中早期候选及失败构建日志不代表交付版本；实际通过构建的日志、布局种子及交付清单以 `manifest.json` 为准。爆音检测增加一拍流水线，避免邻居能量门限和尖峰判断形成过长的组合路径；整数处理结果与样本对齐不变。

## 音频验证

180000 组双声道 RTL 输出与整数参考逐样本一致，最大误差 0 LSB。测试包含旁路、正负满幅、随机双声道、开关渐变、运算中清理、旧曲历史隔离、直流和孤立尖峰。

| 测试信号 | V4 测得变化 |
| --- | ---: |
| 40 Hz 音乐 | −0.037 dB |
| 1 kHz 音乐 | +0.015 dB |
| 4 kHz 音乐 | +0.007 dB |
| 5 kHz 音乐 | +0.018 dB |
| 100 LSB 的轻声 1 kHz 旋律 | +0.033 dB |
| 指定 16 kHz 干扰 | −66.22 dB |
| 1800 LSB、零背景的孤立尖峰 | 输出全为零 |

读取现有电脑音频备份，同一输入和播放增益下，对 BGM1–BGM4 取第 30–40 秒，BGM0 取全部 10 秒；不改变 TF 卡，不对输出做响度匹配。

| 片段 | 原声 LUFS | V3 LUFS | V4 LUFS |
| --- | ---: | ---: | ---: |
| BGM0 噪声测试 | −10.33 | −16.13 | −16.20 |
| BGM1 | −9.43 | −9.74 | −9.58 |
| BGM2 | −14.36 | −14.62 | −14.60 |
| BGM3 | −10.44 | −10.69 | −10.61 |
| BGM4 | −10.56 | −10.63 | −10.63 |

四首音乐片段的响度下降为 0.07–0.24 LU，五段输出均没有满幅样本。BGM0 的 7.5–11.5 kHz 频带能量相对输入降低约 52.65 dB，V3 为 29.54 dB；即这段刻意加入高频噪声的素材，相同频带比 V3 再降低约 23.11 dB。该指标使用去除首尾各一秒、加 Hann 窗后的频谱能量，不能推断所有录音、所有噪声都能降低这么多。

噪声测试曲去掉噪声后总 LUFS 明显下降，但主旋律频段增益保持。更高频的真实音乐细节仍会衰减；更低频的持续滋滋声、削波和丢样不在本算法可完整修复的范围。上述为软件参考及 RTL 仿真，实际 HDMI 录音和实板试听仍待验证。

## 构建与交付

最终文件为 `src/td_project/SAIXIAN_2.0_AUDIO_REPAIR_V4_SHARP_20261010.bit`；只有最终构建资源及时序检查、57 项回归、音频数值/片段比较及最小样本间隔测试全部通过，发布程序才复制这个文件。资源、建立/保持余量及源码和位流 SHA256 以 `validation/audio_repair_v4_20261010/manifest.json` 为准。

最终采用布局种子 12，建立余量 +0.134 ns、保持余量 +0.024 ns，TNS 为零；LUT 16232/19600、寄存器 10303/19600、RAM9K 59/64、RAM32K 11/16、DSP 14/29。57 项完整回归通过，最终流水线调整后另重跑四项音频专项及最小样本间隔测试，均通过。位流为 691316 字节，SHA256 `EF4D83AFA76152F2FECAD97214F51DEC20CE6A2309370260E0AA9408E9641B85`；默认位流与该交付文件一致。

下载新 FPGA 后，在第九项“音频修复”开启或关闭比较，同一音量试听 BGM0 残余噪声和 BGM1–BGM4 清晰度/响度，并检查切歌、暂停、提示音。无需重烧串口屏或更换 TF 素材。旧位流备份在 `validation/audio_repair_v4_20261010/previous_timing_pass.bit`。

python tests/verify_audio_repair.py --work validation/audio_repair_v4_20261010/signals
