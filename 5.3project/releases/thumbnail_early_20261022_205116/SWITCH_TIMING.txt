切屏耗时测量版（基于 bcfb810，使用原版 48 步转场）

用途与固件
  同时下载本测量版 A/B 固件。新固件名称包含 SWITCH_TIMING。
  原 releases 目录下的 5.3 固件是历史基线，不包含本次测量逻辑。
  A/B 工程仍分别位于 src/board_a/td_project 和 src/board_b/td_project。
  不需要增加接线；通过两块板原有的六位数码管读数。

读数格式
  六位依次为：页码 + 五位十进制毫秒数，每页保持 2 秒，循环显示。
  例如 3 00834 表示第 3 页为 834 ms。0 ms 表示小于 1 ms。
  开始新测量后继续显示上次完整结果；页码的小数点亮表示正在测量。
  完成后四项/三项结果一起更新。出错或取消不会发布不完整结果。
  上限为 99999 ms，达到后饱和。分段时间的边界量化误差小于 1 ms。
  数码管位置顺序沿用 photo_status 的 index 0..5。

A 板（三页：实际导航）
  1：接受一次下一张请求 -> 控制器发出该目标图片的显示就绪通知。
     包含排队、等待目标缓存以及必要的传输等待。
  2：该显示就绪通知 -> 对应目标的 frame_commit。
     包含跨域同步、等待帧边界和转场。
  3：本次请求 -> 对应目标的 frame_commit（总耗时）。
  按键、HMI、鼠标点击和自动轮播产生的下一张请求均会测量。
  连续请求采用最新请求；旧图片的显示提交不会结束新请求的测量。
  设置刷新和奖杯切换不作为本版的有效照片导航测量。
  起点在按键消抖/HMI 解析之后；终点是 FPGA 显示缓冲提交，
  不包括 HDMI 接收设备自身的延迟，也不等于新画面最后一个像素输出完成。

B 板（四页：最近一次成功的图片传输）
  1：接受 A 的图片读取请求 -> 图片完整准备好（缓存命中或 SD 加载）。
  2：图片准备好 -> 收到 A 的 READY 并启动传输（握手耗时）。
  3：启动传输 -> 像素发送器报告完成，经既有同步回到 SD 时钟域。
     包括图像处理、辅助效果平面、SDRAM/FIFO 等待和链路反压。
  4：接受图片读取请求 -> 发送完成（前三项之和）。
  B 的后台预取也会测量；它与 A 当前按键导航不一定是同一张图片。
  A 命中本地缓存时，B 可以没有新的传输，所以 B 仍显示此前的结果。
  B 的 COMMIT 包确认的是缓存存储事务，不能当作显示完成时间。

测量方法
  1. 上电等首图和后台预取稳定，再按一次下一张，等 A 页码小数点熄灭。
  2. 记录 A 的 1/2/3 页；A1 接近 0 说明主要耗时在帧同步和转场。
  3. 比较连续快速切图与每次间隔数秒的 A1；快速切图更容易等待缓存。
  4. 读取 B 的 1/2/3/4 页以判断单次图片准备和传输的开销。
  5. 完整测量结果出现前仍显示原有诊断信息；错误、设置菜单和奖杯
     诊断保留显示优先级。错误后需要复位，才能重新建立干净的测量记录。

复现
  python tools/test_switch_timing.py
  python tools/build_switch_timing.py --work <一个全新构建目录>
  构建通过后，releases/switch_timing_日期时间/ 包含专用 A/B bit、
  资源/时序报告、校验值和本说明。功能仿真不代替实板验证。

实现
  计时器在各自控制器时钟域内工作，A 75 MHz、B 100 MHz。
  按 1 ms 分频直接计十进制数，不使用乘法器、除法器或图片缓存。
  结果寄存器只在成功完成时整体发布，显示扫描器与计时器使用同一时钟域。
