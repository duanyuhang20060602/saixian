# 双板音频第一阶段：B 读音频，A HDMI 播放

本版在 MODEFAST 图片版本上增加独立音频 SPI 通道。B 从现有 TF 卡读取音频，A 缓冲并通过 HDMI 输出 48 kHz 双声道音频。默认播放第一首，单曲结束自动循环；A 正常显示时 KEY2 切下一首，末首回到第一首。设置界面中的 KEY2 仍为参数减少。

本阶段未加入频谱、音量调节、提示音混合或独立模拟音频输出。显示器或电视需要支持 HDMI 音频。

## J2 接线

两板同号连接，新增音频信号全部使用 J2：

| 接口 | FPGA 管脚 | 信号 | 方向 |
|---|---|---|---|
| J2-24 | H3 | MOSI / 歌曲请求 | A → B |
| J2-27 | E2 | SCLK，3.75 MHz | A → B |
| J2-28 | J11 | CS，低有效 | A → B |
| J2-31 | J12 | MISO / 音频数据 | B → A |
| J2-12 或 J2-30 | GND | 共地 | 两板共地 |

J2-24 复用此前的 image_ack 线，本版图片完成确认通过已有板间 UART 完成。如果原来 J2-24 和地已连接，只需增加 J2-27、28、31 三根信号线；从零搭建音频通道需四根信号线加共地。两板必须同时烧录名称包含 AUDIO1 的匹配 bit。

**脚号更正：此前文档把 MISO 错标为 J2-29。J2-29 实际是 3.3V 电源，J12 对应 J2-31。代码和 bit 始终约束为 J12；请断电把两板之间的 MISO 线改接 J2-31，J2-29 不用作音频信号。**

## TF 素材及控制

沿用单板 SXAUD001 格式，最多识别五首歌曲：512 字节对齐的文件头，随后为小端有符号 16 位、48 kHz、双声道 PCM。文件头偏移 0 为 `SXAUD001`，偏移 8 为 PCM 字节数，偏移 12 为采样率，偏移 16/18 分别为 16 位及双声道格式字段。

TF 使用现有原始扇区素材扫描，音频头和数据必须连续占据扇区；普通复制 WAV/MP3 到 FAT 目录不能直接播放。附带 [转换器](tools/convert_audio_to_aud.py)，使用 Python 3.12 或更早版本运行 `python tools/convert_audio_to_aud.py input.wav output.aud`。生成后按原单板写卡方式放置；使用 FAT 文件时也必须保证 AUD 文件连续，不能碎片化。

- A KEY2：正常显示时下一首；只有一首时保持当前曲。
- 串口屏下一首事件：`printh 55 08 00 00 ff ff ff`，115200 8N1。
- KEY1/KEY4：下一张图片；KEY3：打开或退出图像设置。
- 上电自动播放第一首，切歌清空 A 的旧缓冲并短暂静音，等待新歌曲数据。

## 缓冲及协议

两板各有 32 KB 音频 FIFO，约可存 170 ms PCM。A 收到至少 512 帧后开始播放，通常维持约 4096 帧（85 ms）缓冲。B 在 TF 扇区边界优先补充音频，图片继续使用原有缓存和 50 MHz 并行链路。音频与图片共用 TF，繁忙读图或存储卡停顿仍可能造成音频欠载，需要实板确认。

音频 SPI 为模式 0、MSB 在前，3.75 MHz。A 请求包含标记、歌曲代号及歌曲编号；B 返回两个 32 位头字段（状态及长度），随后为 0 或 128 个立体声 PCM 帧。每帧低 16 位为左声道，高 16 位为右声道。

本次新增音频通道没有 CRC16，也没有数据校验尾字段。接收端按包头长度接收，歌曲代号及编号用于丢弃切歌前的数据。PCM 直接进入播放 FIFO。没有校验意味着线路上的数据位错误可能表现为杂音；错误包头长度会结束当前包。

## 构建与上板

### AUDIO1_DIAG_BGSCAN：先播放，后台继续扫描

新烧录文件名包含 `AUDIO1_DIAG_BGSCAN`，两板同时更新。找到第一张图片后，在扇区边界暂停扫描，开放已发现图片供 A 显示；找到第一首歌曲后立即启用音频流，不需要凑齐五首。图片所需的 B 原图缓存补齐后，扫描从暂停的位置继续，直到设定的扇区范围结束或六图五曲均找到。

切图请求、背景补图及图像设置会让扫描在扇区边界暂停；已缓存图片可在扫描期间直接交付。暂停保留游标及目录计数，不重置 TF 或音频 FIFO。新图片数量通过板间消息 18 通知 A，A 以消息 19 确认；更新数量不清空现有图片缓存。扫描未完成时只可切换已发现的图片/歌曲，数量会随扫描增长。音频仍在扇区边界优先补充播放缓冲。

正常显示时读取数码管，从左到右：

- A 板：`8 S N T B H`。S 为音频阶段，N 为 A 获知的歌曲总数，T 为当前歌曲编号（从 1 开始，没歌曲为 0），B 为 FIFO 缓冲量的 1024 帧档位（0~8），H 为状态位组合。
- B 板：`7 S N T B R`。S 为 TF/音频阶段，N 为 B 找到的歌曲总数，T 为当前歌曲编号，B 为 FIFO 缓冲量档位，R 为是否曾收到合法的 A 音频请求（0/1）。
- A 打开图像设置后暂时恢复原设置数码管显示，退出后恢复音频诊断。

| A 第二位 S | 含义 |
|---|---|
| 1 | 尚未收到合法的 B 音频状态头，检查两板版本、MISO、SCLK、CS |
| 2 | 收到 B 状态头，但歌曲数量为 0；对照 B 是否还在扫描 |
| 3 | 已得知有歌曲，但尚未收到对应歌曲的 PCM 数据 |
| 4 | 已收到 PCM，正在等待至少 512 帧启动缓冲 |
| 5 | 播放计时器已启动，未记录到缓冲欠载；不代表显示器已实际发声 |
| 6 | 播放启动后曾发生缓冲欠载，直到复位保持此记录 |

| B 第二位 S | 含义 |
|---|---|
| 1 | TF 尚未初始化完成 |
| 2 | 仍在扫描素材；第三位 N 可显示已找到的歌曲数量 |
| 3 | 扫描已结束，没有找到音频 |
| 6 | 扫描已暂停以服务图片，之后还会继续；不代表音频错误 |
| 4 | 已找到音频，但当前缓冲少于 128 帧 |
| 5 | 已找到音频，当前缓冲至少有 128 帧 |

A 最后一位 H：`HPD + 2×HDMI视频锁定 + 4×曾收到非零PCM`，因此取值 0~7。例如 3 表示 HDMI 已连接且视频锁定，但尚未见到非零 PCM；7 表示三个条件都成立。此位不能检测扬声器音量、实际音频包到达显示器或播放是否成功。

判断顺序：B 的 N=0 查扫描/素材；B 的 R=0 查 A→B 请求线路；B 有歌、有缓冲而 A 的 S=1 查 B→A 返回线路；A 的 S=3 查歌曲匹配及数据传输；A 的 S=6 查 TF 延迟及补充缓冲；A 的 S=5、H=7 仍无声则继续定位 HDMI 音频输出。请提供两板完整六位数字及等待时间，动态变化时可拍视频。

编译和时序结果见 VALIDATION.md。本版未运行功能仿真，尚未实板确认 HDMI 声音、声道、切歌、长时间连续播放及图片并行切换效果。建议先使用原有 SXAUD001 素材，上板观察是否有声音，再检查 KEY2 首尾切歌及同时切图的稳定性。
