# B 板图像处理与 A 板 HDMI 设置说明

本版在双板720p高速切换版本上恢复单板的照片处理方式。B 负责TF读图、缩放、图像处理及传输；A负责按键、串口命令、HDMI设置界面及转场。参考单板代码为提交 `d27ae79126429f1a25a65e42f8fe95571da5c0df` 的 `2.0Project/src/user_source/hdl_source/top_tf_hdmi_audio.v`。

## 功能和连接

```text
B：TF读取/缩放 → 原始RGB565 SDRAM缓存 → 发送时展开RGB
→ 自适应增强/保边平滑/锐化 → 亮度/对比度/饱和度
→ 复古/反色 → RGB565重新打包 → 50MHz链路
A：处理后图片缓存 → 转场明暗 → HDMI范围映射
→ 原图分辨率/中文设置界面 → HDMI
```

- B按单板照片模式使用PHOTO_SMOOTH=1，后级额外锐化关闭以避免重复加强。
- B保留未处理的三槽图像缓存，设置期间保护A实际显示图片；正常播放时预取跟随已完成传输的图片，避免固定占用原图槽。参数改变时，在发送路径重新处理；命中B缓存的图片无需重读TF。打开设置暂停后台预取，连续参数变化经过50ms合并后发送。
- 两条1280字节亮度行缓存位于B。每次传输锁存参数，整帧参数一致；32字输出队列和在途字计数应对A反压。
- A通过控制UART发送完整18位图像参数快照，B回传确认。确认后A清空缓存有效标记，优先更新当前图，再预取后面三张。
- 更新期间保留原完整画面，新当前图在视频帧边界直接替换，不播放切图动画。
- A保持21拍显示延迟、最终HDMI范围映射和叠字，图像增强及颜色调节固定旁路。
- 保留50MHz链路、TF连续读取、源分辨率标注、自动轮播和六种转场。音频、动图和鼠标功能未移植。
- B处理结果再次量化为RGB565，精度与原先A直接24位处理略有差别。

## 使用与默认值

默认：增强1、细节1、亮度/对比度/饱和度均4（HMI代表值50）、反色和复古关闭。

| 参数 | 值 | 效果 |
|---|---|---|
| 增强模式 | 0 | 旁路增强模块，包括其平滑/锐化；后级颜色设置仍生效 |
| 增强模式 | 1 | 全屏自适应增强与细节处理 |
| 增强模式 | 2 | 左半不增强、右半增强，分界x=640；后级颜色设置作用于两侧 |
| 细节/锐化档位 | 0 | 不作空间平滑或锐化，增强开启时仍有自适应亮度提升 |
| 细节/锐化档位 | 1 | 照片模式下为保边平滑，减少相近亮度区域的噪声 |
| 细节/锐化档位 | 2 | 锐化：增加一倍局部亮度残差，增量限幅±12 |
| 细节/锐化档位 | 3 | 更强锐化：增加约1.5倍残差，增量仍限幅±12 |

“锐化1”在单板照片模式中实际为平滑；本次保留该含义。增强0时细节档位不产生空间处理效果。恢复默认重新设为增强1/细节1。

A板KEY3进入HDMI设置，KEY1选项，KEY2减，KEY4加，KEY3退出。项目1亮度、2对比度、3细节/锐化、4饱和度、5反色、6复古、7增强；项目8转场、9自动轮播保持现有行为。界面从项目1循环至9，隐藏音量；原音量命令14保留兼容，无音频效果。详见HDMI_SETTINGS_MENU.md。

## HMI 命令

UART115200、8N1，沿用7字节 `55 CMD VALUE 00 FF FF FF`。

| 功能 | CMD（HEX） | VALUE |
|---|---|---|
| 细节/锐化 | 10 | 0..3 |
| 亮度 | 11 | 0..100，量化为9档 |
| 对比度 | 12 | 0..100，量化为9档 |
| 饱和度 | 13 | 0..100，量化为9档 |
| 反色 | 15 | 0/1 |
| 复古 | 16 | 0/1 |
| 增强模式 | 17 | 0..2 |
| 恢复默认 | 1F | 0 |

“锐化”滑条设置minval=0、maxval=3，释放事件：

```text
printh 55 10
prints h_sharp.val,1
printh 00 FF FF FF
```

“增强模式”滑条设置minval=0、maxval=2，释放事件：

```text
printh 55 17
prints h_enhance.val,1
printh 00 FF FF FF
```

设置页保留名称 `settings`；已有的锐化、亮度、对比度、饱和度、反色、复古状态回写保持原接口。新增回写目标 `settings.h_enhance.val` 和 `settings.n_enhance.val`，请创建对应滑条和数字控件、设vscope=1。缺少这些控件时，它们无法显示FPGA实际状态。

命令18在双板版中是转场方式，19为自动轮播；不要沿用单板音频修复按钮的18命令。本次没有自动修改HMI文件。

## 1. 锐化如何实现

先用近似亮度 `Y=(R+2G+B)/4` 构造局部空间细节，两条行缓存和移位寄存器提供上方两行、左侧两列的八个已到达邻点。这是因果窗口，当前像素在窗口右下角，不是居中、对称的3×3卷积。

邻点和当前亮度相差超过24，或越过图片边界时，替换为当前亮度，防止强边缘被平滑到另一侧。

```text
M = floor((8×Y + 八个筛选邻点亮度之和) / 16)
D = Y − M
锐化2：detail = clamp(D, −12, 12)
锐化3：detail = clamp(D + floor(D/2), −12, 12)
```

锐化分支对−3..3的小残差不加强，减少微小噪声。最终同一detail加到R、G、B三个通道并限幅0..255。细节1采用方向相反的约半残差修正，向局部均值靠拢，从而平滑。超过邻点筛选阈值的强边缘可能被保留而不再加强。

这是局部细节增强，会改变边缘附近的明暗；不会增加真实分辨率，也不能恢复丢失的图像细节。

## 2. 图像增强如何实现

B每加载一张缩放图，按每16×16像素取一点亮度（约1/256），累计亮度和及数量，将提升档位与缓存槽一起保存。发送时直接使用该图统计结果，不沿用上一张图片亮度：

| 平均亮度范围 | gain | tone（整数截断） |
|---|---:|---|
| <64 | 3 | floor(P/512)+floor(P/1024) |
| 64..95 | 2 | floor(P/512) |
| 96..143 | 1 | floor(P/1024) |
| ≥144 | 0 | 0 |

其中 `P=Y×(255−Y)`。这个曲线对中间亮度的提升较多，接近纯黑、纯白时较少，减少高光过曝。720p每张图固定采样3600点。

```text
correction = tone + detail
R' = clamp(R + correction, 0, 255)
G' = clamp(G + correction, 0, 255)
B' = clamp(B + correction, 0, 255)
```

因此本项目“增强”由按图自动亮度提升和局部平滑/锐化组合构成；没有使用直方图均衡、CLAHE或神经网络。三个颜色通道加相同修正以尽量保留色差，但限幅仍可能影响饱和度。

后级另外提供手动亮度偏移−64..64、以128为中心的对比度缩放、围绕亮度的饱和度缩放、暖色灰度复古和逐通道反色，均采用整数流水线和限幅。
