# B→A 流程检查与关闭处理对照

基线：已交付的 1280×720 J2_NOCRC_COMPARE；独立工程 J2_NOCRC_NOENHANCE。1366 和旧版源码、bit 未覆盖。

## 静态检查

1. B 缓存仅在像素字数达到 460800、无半个像素对，并收到 SDRAM 写完成事件后标记有效。发送槽锁定至 A 转场提交；预读选槽避开锁定槽。
2. B link sender 在 FETCH 弹出实际 SHOW_AHEAD=0 的读 FIFO，下一拍 LATCH 捕获 32 位字；先发送高16位，再发送低16位。下降沿输出数据/valid，双方上升沿以 ready 接收；无 ready 时保持当前像素。
3. A receiver 检查首像素 SOF、末像素 EOF及 921600 像素计数。两个像素合成 `{first,data}`；待写字未进入 FIFO 时停止 ready，满状态下保持待写字。
4. 接收末像素后进入 WAIT_WRITE，不立即置 rx_done；等 A SDRAM 写完成 toggle 跨域到接收时钟，再置完成。A 控制端等接收完成及匹配的 UART 帧结束消息后提交，转场在 HDMI 帧边界开始。
5. 显示、接收、转场槽的选择及会话/序号检查保持原对照版规则。图片 CRC32 保持关闭；SOF/EOF/长度及 UART CRC16 检查保留。
6. 720p 使用 640 字行跨度，槽地址、倒序行起点和行切换均按4字对齐。此项不代表 1366 工程的 683 字行问题已解决。

以上步骤未发现确定的应用状态机或字序错误，因此这版不修改板间传输和 SDRAM状态机。

## 关闭增强、锐化

A 顶层 sharpness、enhancement 固定为 0，设置控制器相应输出不再接入显示参数。复位及帧边界快照均为0，HMI状态报告锐化0。原照片增强7拍及调整8拍的旁路节拍保留，总 RGB/HDMI控制对齐仍为21拍。综合后相关滤波行缓存被移除，A BRAM9K 从9降为5。

## 仿真

- 实际厂商 RFIFO→B sender→A receiver→实际厂商 WFIFO：2048 字，异步 FIFO时钟、满/空背压，逐字正确。
- 增加2ns接收时钟偏移、3ns数据/控制/ready延迟，2048字逐字检查通过；仅覆盖该组假定延迟，不代表实测线缆参数。
- 完整帧测试同链路：921600 像素/460800字，结果以 VALIDATION.md及日志为准。
- 同步/异步控制及链路仿真：六图循环、100次手动切换、最新方向合并、槽保护、单板复位重建会话通过；控制测试采用短帧。
- A 实际顶层显示测试：强制设置控制器请求增强2/锐化3，显示端仍为0，三行3840像素符合未增强参考，21拍控制对齐通过。

模型未运行加密 SDRAM 核、真实线路延迟/串扰、SD输入和实际视频PHY。这些通过结果不能证明实板横带来自哪里，也不能承诺新bit消除横带。

## 实板对照

两板烧录匹配的 NOENHANCE bit，保持相同SD卡、接线、显示器、棋盘格图和其他参数。

- 横带消失：增强/锐化路径及其行缓存值得重点核查，但布局布线也变化，仍需后续定位。
- 横带不变：显示滤波不是必要条件，优先采集并比较 B SDRAM读回和 A 接收/显示的数据，定位最早差异。

本套是720p诊断对照，实板结果尚未填写。
