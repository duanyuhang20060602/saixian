5.0 双板赛事记分与串口屏改分

基于8797178900367d0686735622de20c8c22e098342，接入a74f498c45c180e79134bc15f489b37c0316d810的单板赛事功能。
新计分场景与原照片轮播、红蓝获胜、3D奖杯、彩带、音乐和SD中文字库共用现有双板工程。
新场景在A板绘制，提示音仍经原SPI交给B板，不复制另一套HDMI、SDRAM、SD卡或音频引擎。

一、接线和文件
A板J1-1/D14接串口屏TXD；J1-2/G11接屏RXD；J1-12接屏GND。115200、8N1、3.3V TTL。
这是串口屏新增功能的全部接线，不使用J2新增接线。原有双板J1/J2连线继续保持。
串口屏电源沿用原有额定电源，不接到信号引脚。计分数字与队名内置，计分模式不新增TF卡素材。
原有中文标题/轮播仍使用B板TF卡GLYPHS.BIN，不改变879版本字库格式和前512MiB扫描范围。
计分场景使用内置队名；原标题/轮播中文仍可接收，在返回照片场景后显示。
最终可烧录文件保持releases/PHOTO_BOARD_A_5_0.bit和PHOTO_BOARD_B_5_0.bit；是否通过本次构建以同目录match_score_20261031/validation.json为准。

二、使用步骤
上电等待原照片轮播就绪，发送 !M:1 加回车换行，进入赛事设置。
用K1、K2选择不同队伍，K3切换30秒/1分钟/3分钟/5分钟，K4短按启动三秒倒计时。
比赛中K1短按主队+1、长按主队-1；K2短按客队+1、长按客队-1；K3暂停/继续；K4长按结束。
串口屏设置与实体按键同时到达时，优先处理串口屏设置。
暂停时仍可修正比分。比分0至999饱和，结束画面锁分并显示获胜队/平局与2D奖杯和彩带。
结果画面K4短按进入下一场设置；设置画面K4长按返回照片轮播。屏端 !M:0 可随时退出。
按键短按在释放后计分，长按约1秒只触发一次，不在释放时补加分。
原照片模式K1/K2/K3/K4功能保留；两模式复用约20ms消抖时间基，模式切换吞掉已按住的手势。

三、串口数据
以下每条是ASCII，末尾必须附真正的CR LF字节0D 0A；不发送字面上的反斜杠r和反斜杠n。
!M:1 进入记分；!M:0 返回照片。
!H:0 至 !H:5 设置主队；!V:0 至 !V:5 设置客队；同名选择忽略，只在设置阶段有效。
队伍编号0至5依次为红队、蓝队、金鹰、飞虎、雷霆、星火；实体K1/K2也可循环选择。
!T:0 /1 /2 /3 依次选择30秒/1分钟/3分钟/5分钟，只在设置阶段有效。
!K:0 开始；!K:1 暂停/继续；!K:2 结束（倒计时中为取消）；!K:3 下一场。
!A:123 把主队改成123分；!B:45 把客队改成45分，只在比赛中或暂停时有效。
!K:4 主队+1；!K:5 主队-1；!K:6 客队+1；!K:7 客队-1。
数值最多三位十进制，无符号无空格；非法值、未完整接收或超时的数据忽略。
一条消息连续发送，不在内部穿插触摸或其它命令；消息之间可以继续使用原55/A6协议和@0:/@1:中文文字。
!A:123的完整HEX：21 41 3A 31 32 33 0D 0A。

四、串口屏按钮与键盘
examples/HMI/赛事记分按钮事件.txt给出按钮释放事件和两个文本输入框的提交事件。
需在屏编辑器中给两个文本框配置数字键盘，再把事件加到现有HMI页面，编译成匹配该串口屏型号的TFT后下载。
本次提供FPGA功能与屏端事件文本，没有生成或烧写新的屏端TFT。仅更新FPGA bit不会凭空新增屏端页面。
两个文本框是待提交的编辑内容；大屏显示FPGA实际比分。现有屏反馈协议未增加比分回读，实体按键改分后不自动刷新这两个编辑框。

五、电脑测试
python tools/send_match.py mode 1 --port COM5
python tools/send_match.py start --port COM5
等待三秒倒计时后：
python tools/send_match.py pause --port COM5
python tools/send_match.py home_score 123 --port COM5
python tools/send_match.py away_score 45 --port COM5
python tools/send_match.py home_plus --port COM5
COM5替换成实际串口号，直接发串口需要pyserial。不加--port时只打印HEX，不向设备发送。
可加--out E:/Codex/Work/score-input.bin生成原始字节文件；--out路径的父目录须已存在。

六、实现与验证范围
十进制转换与进度计算只在消隐时用同一个整数运算单元，避免像素时钟下并行除法。
固定队名和提示文字压入字体ROM的空余区域，双口依次查字符编号和字形，仍只用一块32K ROM。
数字列位置复用一块9K RAM，七段形状复用区域分类；22种常量颜色在流水线中只保存5位索引，输出时恢复24位RGB。
A板音频FIFO的511/512/半满与空满标志通过计数变化预测，同周期数值保持精确；旧SPI核心自动生成A专用版本，B板源文件保持原样。
奖杯和彩带的列参数查表提前一拍，运动更新、输出五拍延迟和每个像素保持原样。
计分场景维持1280x720输出，与旧场景同一34拍相位，帧消隐更新，旧显示/音频链路格式保持。
仿真、资源与静态时序通过不代表已实板验收；新模式仍需用实际串口屏及板卡确认。
