# 流体工程后续移植评估

实施更新：FLUID_PRIORITY 已接入液态金属、卷页、分列翻转，以及可独立开关的音乐边光。下文保留 FLUID_SELECT 基线时的移植评估；本轮具体实现、边界和最终资源以 `delivery/FLUID_PRIORITY_README.md` 及配套构建报告为准。

## 依据与当前边界

参考已获取的 `origin/codex/water-single-11fx-lut-opt`，提交 `a15d24f6bbae56187508928f800aea7c5df8e7af`。代码位于仓库根目录 `liuti/water_single/rtl/`。以下为源码评估，尚未实现其他效果，也没有其增量资源或实板结果。

当前双板版已移植/改造效果平面滤波、旧图行缓存、目标/原生图共享缓存、RGB565 混合、表面光照及水平重建。B 流式生成效果平面，A 使用 8 行旧图缓存、垂直扰动 ±2。波纹几何采用小资源近似，没有原封移植原分支的开方/倒数引擎。

水滴作为菜单第 7 项独立选择，HMI `55 18 07 00 FF FF FF`；默认/恢复默认改回随机。普通 RGB565 的随机池包括水滴并避免连续重复；不满足水滴条件时从随机池排除它。固定水滴在 RGB888 时回退滑动。第一张图及 DLT 领奖牌仍按原路径直接显示。

## 优先移植的画面效果

参考 `water_effect_map.v` 与 `water_extra_effect_map.v`。这些效果主要改变 X 采样坐标，旧图 Y 保持当前输出行，因此通常不需要扩大现有 8 行缓存；新旧图必须都保有完整的效果平面行。仍需适配效果编号、流水线和边界夹紧。

| 内容 | 可复用部分与主要新增逻辑 | 建议 |
|---|---|---|
| 液态金属 | 现有混合/折射/高光；增加随行变化的波浪前沿、窄反射带和阴影 | 下一步首选，视觉变化大，无需大行缓存 |
| 卷页 | 同行反向采样、卷曲边缘及阴影；原版有 32 项小曲线表 | 优先，存储需求小 |
| 分列翻转 | 8 列分时投影，复用混合/高光；投影需要倒数表及共享乘法 | 优先，控制逻辑中等 |
| 整张卡片翻转 | 水平压缩/展开投影，正反图切换、边缘高光 | 适合与分列翻转共享投影器 |
| 手风琴 | 同行水平压缩、折面明暗，复用投影与混合通路 | 在共享投影器之后加入 |
| 飘带 | 分带时序、行内位移、弯曲轮廓表 | 可行，需要对齐分带参数和坐标 |
| 黏性分裂 | 两侧拉开、弯曲开口、局部折射及阴影 | 可行，算术和边界处理较复杂 |
| 玻璃碎片 | 原实现为斜切玻璃块的同行滑移，并非任意方向旋转的物理碎片 | 可移植；若要求真实旋转/纵向飞散，需另做缓存设计 |
| 能量门 | 精确圆形距离平方、环形开口、亮边 | 可行，复用 DSP；需要分阶段处理平方及比较 |
| 隧道 | 新旧图同时水平投影、扩张/收缩与环状光照 | 可行，双源坐标/倒数采样更复杂，放后面 |

上表不表示可以不改代码直接加入。当前双板的 `water_reader` 接到的是固定水滴编号，`water_drop_small.v` 只实现水滴几何与映射。完整几何选择器需要重新接线，但可以继续复用缓存和传输协议。

## 其他可移植内容

### 音乐驱动边缘光：成本较低

`water_edge.v` 根据最终 PCM 的包络，在屏幕边缘叠加平滑的蓝青色呼吸光。它不需要全屏纹理缓存，也不必再加 FFT，可在最终 RGB 合成阶段用于普通/高精度模式。

建议复用现有音频/频带结果，或用 A 实际播放的 PCM 提取简单包络，避免分析缓冲提前导致光效抢拍。128×8 位的小边缘权重表可评估映射分布式 RAM/逻辑，减少对专用块 RAM 的占用。接入时要同时对齐 RGB、DE、SOF、EOL 和坐标，不能只串接颜色数据。

### 静止照片上的自动/手动滴水：可行但不是接个开关

`water_scene.v` 提供两次水滴的中心、年龄、半径和调度。可做成单独开关，通过 HMI/菜单触发，在不切图时显示涟漪。

当前小资源波纹器没有使用原分支的 `drop0/drop1` 调度参数，显示控制也只在切图时进入流体路径。因此需要同时改波纹器、时间轴、静态显示的缓存选择和持续读图调度。两滴重叠时总 Y 位移仍必须限制 ±2，或另行扩大缓存。静止时持续做纹理渲染会增加显存负载，不宜默认常开。

### 更自然的圆形波纹：值得单独优化

可移植 `water_math.v` 的精确距离及归一化思路，改善当前多边形距离近似。原代码有开方流水线、倒数/正弦/波形表，不是零成本升级。建议先尝试共享平方/DSP、短表或分段近似，保留现有小垂直扰动；不要为追求原版形态直接恢复 32 行缓存。

### 可复用的工程优化

- 几何通路每两个时钟处理一个像素组，两个计算时隙共享乘法器和表读取端口。
- 稳定的帧参数快照、端点回到原生图、行缓存归属及令牌流水线，可继续用于新增效果。
- 不复制整套视频、SD 或音频子系统；双板版已有相应功能，增加重复模块没有收益。
- 原 `water_image_writer.v` 使用 64 字写授权，不能直接替换当前已修复白条的四字分组与停顿方案。原分支 SDRAM 控制、PLL 和复位也不整体替换。

## 资源与接口约束

上轮 FLUID_DROP 实测 A：13201 LUT、11043 REG、57 RAM9K、14 RAM32K、12 DSP；B：13007 LUT、8963 REG、60 RAM9K、12 RAM32K、10 DSP。

A 仅剩 7 RAM9K、2 RAM32K，B 剩 4 RAM9K、4 RAM32K。新增效果应共享几何表、投影器、光照及现有行缓存，尽量只增加 LUT/寄存器/DSP。不能据此保证完整 11 效果都能布线通过；已有时序余量只有约 0.1 ns。

若保留 6 种原切换并加入流体分支全部 11 种效果，再加随机，共 18 个选择状态，建议将选择编号一次扩到 5 位。菜单、HMI、过渡控制和读图模式一起适配，保留现有 0–7 的含义。当前本轮只整理第 7 项，没有提前扩展或实现其他效果。

建议顺序：**音乐边缘光（可独立开关）或液态金属 → 卷页 → 共享投影器及分列/卡片翻转 → 其他效果 → 静态双水滴与更自然几何**。前两项可以按更偏好氛围或切图效果分别选择。

## 后续实施：FLUID_SECOND

按用户确认接入卡片翻转（11）、手风琴（12）、飘带（13）。三者扩展已有 `water_priority_map`，共用分列倒数表及一套投影乘法器；飘带的 t² 与其他效果的坐标×倒数在同一个乘法表达式中按效果选择。弯曲轮廓使用原分支 90 项小表，以逻辑实现。六周期输出契约、八行旧图缓存和目标图行缓存不变，不为每种效果复制渲染器。

本版另按用户要求将 A/B 的 RGB565 写后额外等待设为 0，RGB888 保留 10，门限随写请求锁存；保留四字写组与刷新/仲裁/读对齐。48 级转场保留。实际构建结果、资源和实板边界见 `delivery/FLUID_SECOND_README.md`；不能将前版的白条修复实板表现直接当作零等待版的验证结果。
