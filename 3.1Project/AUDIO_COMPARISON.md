# V3.1 双板与 KEY2-TF 单板的频谱、波形和音频修复差异

对比日期：2026-10-15。参考单板：`fpga/key2-tf-animation` 的 `d27ae79126429f1a25a65e42f8fe95571da5c0df`，目录 `2.0Project`。当前双板：V3.1 发布提交 `0769b821bd918b2fad4a1af4e8411528ac60405d`，目录 `3.1Project`。本次仅阅读、计算和记录差异，没有移植或改变 V3.1 音频算法。

## 结论

两边不仅界面不同，信号处理也不同。单板接入了真正的 1024 点 FFT、双声道峰谷波形和可开关的音频修复链；当前双板保留较早的轻量显示与音量／提示音处理，没有移植这三项升级。

| 项目 | 参考单板 2.0Project | 当前双板 V3.1 |
|---|---|---|
| 频谱算法 | 两声道分别去直流、Hann 窗、1024 点 radix-2 FFT，合并能量，32 频带，近似对数高度 | 实际左声道 PCM 的过零周期估频、峰值包络，再生成主峰和邻近柱高度；没有 FFT |
| 频谱观感 | 能同时反映多个频率成分；柱高度平滑衰减、独立峰值保持 | 能随音乐响度和估计音高变化，但不能解释为 32 个频带的真实能量 |
| 波形输入 | 左右各 16 位 PCM，1024 个采样构成一帧 | 左声道 PCM 的高 8 位，隔 16 个采样取一个，保留 64 点 |
| 波形画法 | 每 4 个采样保留最小／最大值，形成 256 组双声道峰谷；带触发和超时采集 | 单声道抽点连贯显示，缺少峰谷保留和过零触发；512 像素区间每 8 像素对应一个采样点 |
| 波形帧一致性 | 双缓冲，在视频帧边界切换 | 同样已有双缓冲与帧边界切换，并非完全没有防撕裂 |
| 音频修复 | 背景音乐进入去尖峰、去直流、63-tap FIR、软峰值保护，支持干湿渐变 | B 板背景音乐／提示音混合和音量缩放；没有上述修复器，也没有修复开关 |
| 音量档位 | 0、0.25、0.5、0.625、0.75、0.875、1、1.125、1.25 倍；宽位中间量和饱和输出 | 0、0.0625、0.125、0.25、0.5、0.625、0.75、0.875、1 倍；最大不超过原幅度 |

参考单板 FFT 和波形读取的是修复／混合／音量处理后送往 HDMI 的左右 PCM，因此修复和音量变化会同步反映在显示中。当前双板也使用实际 HDMI 输出 PCM 做电平和波形，但仅接入左声道、轻量估频和抽点显示。

## 音频修复具体能产生什么效果

`saixian_audio_repair.v` 的代码包含：

1. 邻域判断去孤立尖峰：中间采样与两边差异很大，且两边彼此接近时，用邻域均值替换中间值。针对孤立点击／尖刺，不能等同于恢复任意失真。
2. 慢速直流跟踪与相减：抑制 DC 偏置和极低频漂移。
3. 63-tap 对称 FIR：抑制高频内容，也可能让原本明亮的音乐听起来更柔和。
4. 软峰值保护：约在 signed-16 的 ±31500 开始压缩峰值，最终饱和到 16 位范围，避免数值回绕。它不能还原已经丢失的削波细节。
5. 干湿过渡：开关变化时，每采样改变 1/256 的混合比例；48 kHz 下约 5.33 ms。干湿路径按 32 个采样对齐，算法注释给出约 0.667 ms 的采样延迟。

根据源码中实际 Q12 FIR 系数计算线性频率响应（不是实板听感测量）：DC 系数和为 4096，1 kHz 约 +0.01 dB，4 kHz 约 +0.01 dB，6 kHz 约 -2.37 dB，8 kHz 约 -60.21 dB。也就是说，它会明显压低 8 kHz 附近内容，不能把它描述为“保留全部高频细节的通用修复”。实际总效果还受到去直流、去尖峰、软限幅和开关状态影响。

**参考单板的修复开关默认关闭。** 设置中启用后才有上述湿声修复效果。音量档位的增强是另外一项变化，不能把“更响”误认为修复效果更好。

## 双板已经具备的音频稳定性处理

当前双板并非没有做音频稳定性处理：

- B 板以音频扇区优先的方式仲裁 TF 访问；SPI 每次传 128 个 PCM 帧。
- A 板按 48 kHz 消费 PCM，达到缓冲门槛后启动播放，并统计欠载。
- epoch／曲目匹配阻止旧批次音频混入新曲目；B 板在当前音频扇区和 SPI 包完成后再切换，切歌不重置 TF。
- 提示音按准备的 PCM 帧推进，背景音乐与提示音混合时各减半以留出幅度余量。

这些处理解决的是传输、缓冲、切歌和混音时序，不等同于单板新增的去噪／去尖峰／FIR 修复。音频修复也不能代替解决缓冲欠载和丢样。

## 如果后续移植，建议的接入方式

- FFT 与双声道波形放在 A 板，直接读取送 HDMI 的左右 16 位 PCM；复用单板帧边界发布和峰值保持。不能只替换 OSD 画图模块。
- 修复可优先放 B 板，但必须增加处理完成后的 PCM 队列／提前处理。现有 B 板只为 4 级音量混音流水预留了极短准备窗口，单板 FIR 注释给出的处理耗时约 301 个时钟，不能直接替换到现有 `sample_prepare → processed_pcm` 四级路径中。
- 单板修复器要求输入间隔不少于 320 个处理时钟；TF 数据是突发流，移植时要显式调度，不能直接把每个突发有效字节当音频采样时钟。
- 若修复放在 A 板，则要按 `out_valid` 和固定采样延迟对齐 HDMI 48 kHz 接口。
- 先保持现有 V3.1 基线与位流，再分别验证可视化与修复，确认资源和时序以及实际听感后发布新版本。
