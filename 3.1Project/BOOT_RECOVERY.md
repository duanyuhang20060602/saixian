# V3.1 启动恢复版

用户反馈 RGB888_LINK_FIX 无法结束启动，A=855147，B=41004C，偶见765141。B 的 41004C 对应图片协议多次收到 NACK、重试耗尽（控制错误4）；不是音频扫描错误。音频页不能提供 A 板具体拒收原因。

**用户已上板确认：本版启动卡住问题解决。高精度切图白条、闪黑仍是未解决的已知问题，详见 [KNOWN_ISSUES.md](KNOWN_ISSUES.md)。**

本次撤回 LINK_FIX 新增的两项未经板上确认的行为：整周期寄存接收许可，以及根据读响应计数结束 SDRAM 突发。common/photo_link.v 和 A 板全部 SDRAM 读写/仲裁源码逐字节恢复到 dual_rgb888_switch_fix，即用户反馈过可以启动但高精度 KEY1 有白条的版本。B 板保持已确认 BOOT_AV_SYNC 位流。

保留 PHOTO ERROR/奖杯错误区分、已接收错误包处理、失败时取消确认和当前有效图片保留。保持此前透明频谱波形、六种高精度转场及开机音画同步。

增加首错诊断：如果开机图片失败，A 板保存第一次错误并显示 `480SEC`，S 是当前图片控制状态（十六进制），E 是首次错误码。3 表示像素帧标记/接收故障，5 表示接收完成或显存写完成等待超时，2 表示接收器未能就绪。启动成功后恢复普通状态页。

仅更新 A 板 BOOT_RECOVERY 位流。此候选目标是撤回启动回归并保留有效诊断；高精度切换的白条/闪黑尚未证明解决，不能当作已完成板上验收。验证报告包含源码字节比对、A/B 控制器及 UART 失败恢复测试、开机音画同步回归、当前模型下的显示/预取测试和最终编译时序。
