# 波形/频谱更新修复候选

## 问题与修改

用户反馈 FLUID_SECOND6 音乐正常、波形和频谱长时间停住。源码检查发现：A 的快照发布受 B 的累计发送位置控制；B 计数包含实际发送而非 A 已接受的数据，在拒收/中断后两侧计数可能偏移。A 只有四个快照缓存，未来时间戳可能延迟发布和缓存释放。此外每次尝试分析包都会清零八包轮询计数，CRC 失败后不能立即重试；包间 CS 高电平此前仅一个 A 时钟，给两端过采样识别留下很小余量。上述是源码识别的风险，不是板上抓取证明的唯一根因。

1. A 在 PCM 真正写入本地 FIFO 时累计 received_position，随曲目/控制 epoch 重置。开始分析包时锁存该位置作为发布时刻，与 play_position 使用同一计数基准，不再用远端累计发送数阻塞发布。保留远端时间戳字段和 CRC，协议长度不变。
2. 分析包只有头/epoch/CRC 均有效后才清零轮询计数。失败请求保持到期状态，缓存有空位且 PCM 水位至少 512 时及时重试；水位不足优先恢复 PCM。
3. 成功 PCM 包和分析包之间保留约 1 微秒 CS 高电平，让两端过采样同步器可靠识别新包边界。

## 保留功能

RGB565 六周期、RGB888 十周期写后额外等待；48 级转场；卡片翻转 11、手风琴 12、飘带 13；此前流体、音乐边光和红蓝获胜/百米动画均保留。J2/TF/HMI 不变，两板完整重新构建。

## 验收

本轮未运行新的功能仿真，未取得实板 CRC/计数抓取。最终静态时序通过后打包，实板需确认波形和频谱连续变化、切歌恢复以及长时间播放；不将候选修改描述为已在板上修复。旧 FLUID_SECOND6 配套包保留。
