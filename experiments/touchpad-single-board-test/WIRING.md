# 单板触控测试：物理接线与烧录

适用固件：`TOUCHPAD_SINGLE_BOARD_TEST.bit`。开发板为现有 HX4S20 / EG4S20BG256 的 HDMI 输出板（原 A 板），串口屏为 TJC8048T070，HMI工程为 `hmi/MOUSE.HMI`。

本版本独立运行，上电直接输出测试界面。只需一块 FPGA 板，不连接 B 板或板间排线，不需要 TF 卡；不测试原系统的照片、SDRAM、音频或双板通信。

## 1. 最少接线

断电后接线，核对板上接口方向和丝印再上电。

```text
TJC8048T070 串口屏                 HX4S20 FPGA板（原A板）

TX  ──────────────────────────>  J1-1 / D14 / hmi_uart_rx
GND ───────────────────────────  板上明确标为GND的引脚
RX  <──────────────────────────  J1-2 / G11 / hmi_uart_tx（可不接）

屏电源 ── 按屏的额定要求供电        FPGA板 ── 按开发板要求供电
                                   HDMI接口 ── HDMI线 ── 显示器
```

| 屏端/设备 | FPGA端 | 必需 | 用途 |
|---|---|---|---|
| 屏 TX | J1-1，FPGA球位 D14 | 是 | 屏把触点帧发送给FPGA |
| 屏 GND | 板上GND | 是 | 两端共同信号参考地 |
| 屏 RX | J1-2，FPGA球位 G11 | 否 | 本测试固件TX保持空闲，不发屏端文字指令 |
| HDMI显示器 | 板载HDMI接口 | 是 | 显示光标、按钮与统计 |
| 下载器 | 板载JTAG/下载接口 | 烧录时需要 | 按现有开发板下载方式写入位流 |

J1-1/J1-2沿用已有工程的接口映射，约束文件最终对应D14/G11。不要按排针外观推断方向；若你的板卡修订不同，以板上丝印、原理图和实际连通性为准。未指定GND的排针编号，使用明确标注的GND。

**D14/G11配置为LVCMOS33。** 确认屏TX输出与3.3V输入兼容；若为5V逻辑，屏TX至D14之间使用适合推挽UART的电平转换。屏电源电压和串口逻辑电平不是同一个概念，不向FPGA GPIO接入屏幕电源。屏幕和FPGA各按额定要求供电，并共地。

## 2. 用CH340和SSCOM监听

```text
屏 TX ──────┬────> FPGA D14
            └────> CH340 RXD
屏 GND ─────┬───── FPGA GND
            └───── CH340 GND
CH340 TXD：悬空
```

监听时不要让CH340 TXD和屏TX同时驱动D14。确认CH340接收输入的电平兼容；不要直接并联两路供电输出。SSCOM选择115200、8N1、无流控、十六进制显示。CH340不是正常运行的必需设备。

屏与FPGA配合测试时，应能看到随滑动变化的十字节帧：

```text
A6 XL XH YL YH DOWN SUM FF FF FF
```

例如原始触点(472,273)：

```text
A6 D8 01 11 01 01 92 FF FF FF  按下/按住
A6 D8 01 11 01 00 91 FF FF FF  松手
```

X/Y为16位小端原始屏坐标，X<800、Y<480，DOWN为0或1；SUM是前六字节相加取低8位。按住建议每20ms发送一次，松手发送DOWN=0。

## 3. 烧录FPGA与串口屏

1. 从本测试版Release下载 `TOUCHPAD_SINGLE_BOARD_TEST.bit`，写入原A板。只烧录这块板，不需要B板位流。
2. 若屏已经运行本次验证过的触控界面，无需重复下载。否则在陶晶驰编辑器打开 `hmi/MOUSE.HMI`，核对型号和115200、8N1设置，编译生成TFT，按屏的下载方式写入。`.HMI`是可编辑工程，不是可以直接替代TFT下载的镜像。
3. 单板固件默认启用触控，不必先发启用命令。现有页面发送 `55 31 01 00 FF FF FF` 也兼容；`55 31 00 00 FF FF FF` 会关闭触控，再次进入页面时应恢复启用。
4. 接上HDMI并上电，应直接显示 `SINGLE BOARD TOUCHPAD TEST`。滑动触控区移动白色箭头，轻触RED/GREEN/BLUE使对应按钮变亮，点CLEAR清零。

本端未编译或修改用户提供的MOUSE.HMI，不提供未验证的TFT镜像。用户串口捕获已验证连续坐标与松手数据；具体HMI事件以实际保存的工程为准。

## 4. 正常现象与定位

| 现象 | 检查方法 |
|---|---|
| 画面正常但RX不增加 | 检查屏TX→D14、共地、115200、页面是否发A6帧 |
| RX增加且RAW坐标变化，但光标不动 | 检查MODE是否为1、DOWN是否为1、是否持续发送按住坐标 |
| MODE为0 | 重新进入触控页，或发送 `55 31 01 00 FF FF FF` |
| ERR持续增加 | 检查校验和、帧长、帧尾、波特率和线路电平 |
| 轻触不计数 | 接触需至少20ms且小于250ms；整次偏移不超过8个屏像素，必须有松手帧 |
| 按住滑动后松手没有点击 | 属于预期行为，拖动不应被识别为轻触 |
| t_tip不变 | 本固件只接收触点，不回写屏端文字；观察HDMI诊断行 |
| 显示数值似乎不符合十进制 | 本版数值均为十六进制，例如0280=640、0168=360 |

## 5. HDMI与时钟约束

使用板载接口，无需手工连接HDMI差分线。工程约束为：50MHz输入时钟R7；HDMI时钟P端K1，D2_P为B3，D1_P为E3，D0_P为F5；DDC SCL为P1，SDA为R1。视频PLL生成75MHz像素时钟和375MHz串化时钟。固定1280×720模式，沿用原工程的HDMI编码/串化逻辑。

本次最终构建：LUT2201、REG666，RAM9K/RAM32K/DSP均为0；建立时间WNS +0.267ns，保持时间WNS +0.027ns，建立/保持总违例均为0。工具验证通过，实板接线、显示兼容性与触控体感仍需按上述步骤验收。
